##### File: database/sql/add_payment.sql

##### Create new migration file in database/sql/ path


```
create table if not exists payment (
id bigint primary key generated by default as identity,
invoice_id bigint not null references invoice(id) on
delete cascade,
payment_date date not null,
amount numeric(12,2) not null,
method text,
note text
);
```

Reading req.query
Reading req.body
Validating input data
Calling the service layer
Sending the response back

through pool.js.
6 .The result comes back to the

# Adding new

# endpoint / module


```
If you want to add a new feature to the
backend, the first thing you need is a new
route.
The route maps an endpoint to a controller.
For example, if we want to build a payment
module, we might have GET /api/payments,
POST /api/payments, and GET
/api/payments/:id.
```
## Step 1: adding new route

##### Path: server/src/routes/payments.routes.js (create)


```
Next, the controller is the layer that receives the actual request and then calls the service.
If the feature has a request body that needs validation, we can also add a model schema and parse the
data before calling the service, just like in other modules.
```
## Step 2: adding new controller

##### Path: server/src/routes/payments.controller.js (create)


```
The service layer is where the database is actually queried.
Here we import pool from server/src/db/pool.js and use pool.query() to send SQL to PostgreSQL.
So if you want to add a new module,the service layer is one of the most important parts you need.
```
## Step 3: adding new service

##### Path: server/src/routes/payments.service.js (create)


```
After adding the route, controller, and
service, do not forget to register the new
route in app.js.
Otherwise, the new endpoint will not be
active yet.
```
